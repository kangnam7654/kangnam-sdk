# Migrating to llm-router v0.4.x

This guide covers breaking changes downstream consumers need to apply when
upgrading to **v0.4.0** (tool calling + multimodal + `ChatMessage` refactor)
and **v0.4.1** (`ToolChoice` `#[non_exhaustive]`).

If you are upgrading from a version **older than v0.3.x** (e.g. v0.1.x or
v0.2.0), also read the [Pre-v0.3.x → v0.4.x extra changes](#pre-v03x--v04x-extra-changes)
section at the end of this guide. The Lunawave migration discovered these
weren't covered by earlier release notes.

## Required changes (mechanical)

### 1. `ChatMessage` literal → constructor

**Before (v0.3.x)**:
```rust
let messages = vec![
    ChatMessage { role: "user".into(), content: "hello".into() },
    ChatMessage { role: "assistant".into(), content: prev.clone() },
];
```

**After (v0.4.0)**:
```rust
let messages = vec![
    ChatMessage::user("hello"),
    ChatMessage::assistant(prev),
];
```

### 2. Reading `msg.content` as String

**Before**: `msg.content.clone()` or `&msg.content`
**After**: `msg.text_content()` (returns `String`, concatenates Text blocks, skips others)

### 3. `LlmStreamEvent` exhaustive match

**Before**:
```rust
match event {
    LlmStreamEvent::Delta { text } => ...,
    LlmStreamEvent::End { total } => ...,
    LlmStreamEvent::Error { message } => ...,
}
```

**After**: Add a `_` arm to handle new variants (`ToolCall { call }`, plus future ones):
```rust
match event {
    LlmStreamEvent::Delta { text } => ...,
    LlmStreamEvent::End { total } => ...,
    LlmStreamEvent::Error { message } => ...,
    LlmStreamEvent::ToolCall { call } => ...,  // NEW
    _ => {} // optional safety net for future variants
}
```

### 4. `ToolChoice` exhaustive match (added in v0.4.1)

`ToolChoice` is now `#[non_exhaustive]`. External code that exhaustively
matches on this enum needs a `_` arm.

**Before (v0.4.0)**:
```rust
match opts.tool_choice {
    Some(ToolChoice::Auto) => ...,
    Some(ToolChoice::Required) => ...,
    Some(ToolChoice::None) => ...,
    Some(ToolChoice::Specific(name)) => ...,
    None => ...,
}
```

**After (v0.4.1+)**:
```rust
match opts.tool_choice {
    Some(ToolChoice::Auto) => ...,
    Some(ToolChoice::Required) => ...,
    Some(ToolChoice::None) => ...,
    Some(ToolChoice::Specific(name)) => ...,
    Some(_) => {} // NEW: handle future variants
    None => ...,
}
```

This rarely affects callers — most code only constructs `ToolChoice`
values rather than matching on them.

## Optional new features

### Tool calling

```rust
use llm_router::{ChatMessage, ToolDef, ToolChoice, LlmRequestOptions};
use serde_json::json;

let opts = LlmRequestOptions {
    tools: vec![ToolDef {
        name: "get_weather".into(),
        description: "Get weather for a city".into(),
        input_schema: json!({
            "type": "object",
            "properties": {"city": {"type": "string"}},
            "required": ["city"]
        }),
    }],
    tool_choice: Some(ToolChoice::Auto),
    ..Default::default()
};

let response = provider.chat_with_options_dyn("", &messages, &opts, &json!({})).await?;
for call in &response.tool_calls {
    let result = execute_my_tool(&call.name, &call.arguments);
    // Send back in next turn. IMPORTANT: include the model's full assistant
    // turn (any text it produced alongside the tool_calls) — otherwise the
    // conversation history becomes inconsistent and Anthropic/OpenAI may
    // reject the next request. Use `response.rendered_text` if non-empty.
    let mut next = messages.clone();
    if !response.rendered_text.is_empty() {
        next.push(ChatMessage::assistant(response.rendered_text.clone()));
    }
    next.push(ChatMessage::tool_result(call.id.clone(), result, false));
    // ... pass `next` to the next chat_with_options_dyn call ...
}
```

> **Note**: `call.id.clone()` (owned) and `call.id.as_str()` both work since
> `ChatMessage::tool_result` accepts `impl Into<String>`. The above uses
> `clone()` for clarity.

### Image input (HTTP providers)

```rust
let image = ChatContent::image_from_path("photo.png")?;  // or image_from_base64_auto
let messages = vec![ChatMessage::user_with_image("describe this", image)];
let response = provider.chat_with_options_dyn("", &messages, &opts, &json!({})).await?;
```

## Per-provider notes

- **Anthropic (`claude`)**: full tool calling support; URL images supported (added 2024).
- **OpenAI (`codex` Responses API)**: tool calling via Responses API schema (`name` flat, not nested under `function`).
- **OpenAI (`openai_compat` Chat Completions)**: standard tool calling; `tool_result` becomes separate `role: "tool"` message.
- **Gemini**: `ChatMessage::tool_result(name, ...)` — pass the function NAME as `tool_use_id` since Gemini pairs by name. URL images NOT supported (use Files API).
- **Copilot**: tool calling marked experimental — API tier-dependent.
- **`_local` providers**: ignore `tools`/`tool_choice` (CLIs handle their own tools internally). Tool result blocks dropped with debug log.

## Validation

After upgrading, run:
```sh
# In your Cargo.toml, ensure:
# llm-router = { git = "...", tag = "v0.4.1" }

cargo build --release
cargo test
```

If anything still fails, check the rustdoc for specific provider modules — most edge cases are documented at the module level.

## Pre-v0.3.x → v0.4.x extra changes

If your project is on **v0.1.x or v0.2.0** and is jumping straight to v0.4.x,
there are two additional breaking changes that landed in v0.2.0 (not covered
in the v0.4.0 sections above). Apply these alongside the v0.4.x changes.

### 1. `create_provider` gained a 4th argument (added in v0.2.0)

**Before (v0.1.x)**:
```rust
let provider = create_provider("openai_compat", &api_key, &model)?;
```

**After (v0.2.0+)**:
```rust
let provider = create_provider("openai_compat", &api_key, &model, &base_url)?;
```

`base_url` is the only required field for `openai_compat` (e.g. LM Studio,
vLLM, Ollama-compat endpoints). Other providers accept an empty string `""`
to fall back to their built-in default URL.

```rust
// Most providers — pass "" to use the default URL:
let provider = create_provider("claude", &api_key, "claude-sonnet-4-5", "")?;

// openai_compat — base_url is required:
let provider = create_provider("openai_compat", &api_key, &model, "https://api.example.com/v1")?;
```

### 2. `LlmResponse` gained new fields (v0.2.0 + v0.4.0)

If your code constructs `LlmResponse` literals (rare — usually only test
fakes or mock providers do this), add the new fields:

```rust
LlmResponse {
    rendered_text,
    model,
    estimated_cost_usd,
    input_tokens: None,    // NEW in v0.2.0 — Option<u32>
    output_tokens: None,   // NEW in v0.2.0 — Option<u32>
    tool_calls: Vec::new(),  // NEW in v0.4.0 — Vec<ToolCall>
}
```

Or use `..Default::default()` for forward compatibility:
```rust
LlmResponse {
    rendered_text,
    model,
    estimated_cost_usd,
    ..Default::default()
}
```

`LlmResponse::default()` was added in v0.4.0 (`#[derive(Default)]`).
For v0.2.0–v0.3.x, write explicit fields.
